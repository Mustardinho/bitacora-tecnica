## Cómo se usa este repositorio

1. **Cada hito del calendario es un issue** con su milestone y su fecha límite. El tablero de GitHub Projects es la vista de trabajo diaria.
2. **Cada bloque de estudio termina en un commit.** Si una sesión no deja rastro en el repo (nota, ejercicio, código), no cuenta como sesión.
3. **Cada domingo, 20 minutos de revisión:** cerrar issues completados, rellenar la entrada semanal en `bitacora/`, actualizar la tabla de progreso de este README.
4. **Regla del alcance:** las fechas no se mueven. Si una quincena se tuerce, se recorta el alcance de esa quincena.

---

## Reglas de ejecución

- 1 h de teoría → 2 h de aplicación. Si un tema no se puede tocar con las manos, se pospone.
- Un día perdido no se recupera. Dos días seguidos perdidos → se recorta el alcance, no se aplaza la fecha.
- Los bloques van en el calendario como eventos con hora fija, no como intención.
